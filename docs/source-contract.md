# MassDeclaration 来源约定

此服务管理装箱资料准备、门户表单交互及箱级受理核对。
目录请求为 `GET /yard/weighings`，返回 `approval` 与 `weighings`。每个目录成员以 `id`、`href` 提供来源身份与原文位置，原文中的 `weighing` 和 `approval` 必须与目录一致。换箱或拆箱后重新核准的箱可以在目录成员上给出自己的 `approval`，仍须与对应原文一致。

## 记录含义

```json
{
  "weighing": "W100",
  "approval": "AP1",
  "container": "BOX1",
  "seal": "SEAL1",
  "cargoKg": "18000",
  "tareKg": "2200",
  "approved": true
}
```

这里的字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。领域解释保留称重核准依据、货重与皮重、箱号封志回读。只有所选范围内且有充分常规依据的记录列入当前收件；其他范围、待确认、历史和冲突分别保留结果，不用覆盖旧原文消除分歧。

换箱或拆箱后的箱记录还可以带有 `packing`（哪次装箱）、`approvalVersion`（该组核准依据的修订号）、`replacement` 以及 `origin`（由哪一次称重产生）。可选字段只在来源确实提供时保留；缺少货物重量时结果为 `review`，绝不用原总重差额补齐。新箱必须有自己的称重身份与核准修订，沿用原箱称重身份或同一组旧依据不能成为 `accepted`。

## 拆装关系

同一来源可以发布关联资料，目录用 `relations` 引用它们（也可挂在单条称重上）；示例位置为 `/yard/weighings/relations/W100`：

```json
{
  "origin": "W100",
  "approval": "AP2",
  "approvalVersion": 2,
  "restuffings": [
    {
      "from": "BOX1",
      "to": [
        {
          "container": "BOX2",
          "weighing": "W200",
          "seal": "SEAL2",
          "packing": "PK2",
          "cargoKg": "10000",
          "tareKg": "2400",
          "approval": "AP2",
          "approvalVersion": 2,
          "approved": true
        },
        {
          "container": "BOX3",
          "weighing": "W300",
          "seal": "SEAL3",
          "packing": "PK3",
          "tareKg": "2300",
          "approval": "AP2",
          "approvalVersion": 2,
          "approved": true
        }
      ]
    }
  ]
}
```

`to` 只有一个成员表示换箱，多个成员表示拆箱；成员可以只写箱号，也可以给出该箱自己的称重身份、封志、装箱、货重与皮重。未给出的重量就是未知，不能为了凑平原总重分配。目标箱货物重量合计超过原称重时，整组标为 `conflict`；同组中没有任何缺重或冲突的箱仍按各自依据继续办理。

同一原箱收到多份拆装资料时只采用核准修订最新的一份；同版本内容互相排斥时相关目标箱标为 `conflict`，不挑选其中一份。被换下或拆开的旧箱：原文与收据继续保留，但决定改记为 `superseded`，不再作为有效申报，也不支撑新箱的已核准状态。

`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟与 `replace` 更新资源；访问记录保留实际请求路径，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。目录不承诺所有关联资料与当前目录同时发布；HTTP 404、403、503 不能自行解释为业务删除。关联资料未取得时，无法判断旧箱是否已经换箱或拆箱，相关待办保持 `review`，不会替人认可旧范围下的资料。

## 原文和收件

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录与决策。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。一次办理的范围可以是单只箱号，也可以是换箱/拆箱后的一组箱号；存储按规范化后的范围保存收据。同一箱只保留一份 `accepted`，新依据受理后旧结论改记为 `superseded`，原始收据与原文仍可追溯。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。

## 门户操作

`portalServer` 是本机合作门户，表单按来源业务身份打开，控件有可见标签。受理对象由箱号与封志体现，页面修订号代表当前核准依据；保存草稿和确认提交为不同操作，修订号变化会使旧页面、旧草稿和旧回执失效。草稿与提交都不能绕过界面改写受理对象、封志或核准依据。状态、依据和回执由服务端保存，浏览器回读后才能确认；`data-basis` 给出回读时的依据，`data-receipt` 给出实际受理的箱、装箱、依据与关联去向。`revise` 用于测试中模拟人工合法修订，服务端保留操作记录。页面的关联行来自现场已有记录，可以选择关联对象与去向；显示的来源记录不授权客户端绕过界面修改后端存储。
